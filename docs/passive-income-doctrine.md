# Passive Income Doctrine

This project earns only what lands on-chain in the published
USDT/USDC wallet. Everything else is a lead, a channel, or a refusal.

## Principles

1. **Measure the funnel, not the last stage.** Views are measured; what
   happens after a reader reaches the footer is not. Attribution is
   correlated context, never per-post proof.
2. **Income must run unattended.** A channel that earns per sale with no
   owner in the loop beats one that pays more per hour of the owner's time.
   Selling the owner's hours is a job, not passive income.
3. **Name where the money lands.** Prefer stablecoin to the address this
   project already publishes. A second address is a second meter.
4. **State every cost and every manual setup step out loud.** Zero budget is
   the binding constraint. A published cost is honest; an estimated one is a
   fabrication.
5. **Reuse output already produced.** The articles, the README, the release
   notes, the wallet footer -- these are the distribution layer. Do not build a
   new surface to say the same thing.
6. **Stay inside policy.** No social posting, no trading, no minting, no cold
   outreach. Research, draft, publish to dev.to. That is the whole surface.
7. **On-chain or nothing.** Listings, views, and pipeline are not revenue.

## Refused channels

- **Sellix** -- seized and shut down in 2024.
- **Coinbase Commerce** -- defunct for non-US/Singapore merchants.
- **CoinPayments** -- geo-dead and KYC-mandatory under MiCA.
- **kofi.network** -- impostor risk, not affiliated with ko-fi.com.
- **NOWPayments (direct)** -- custodial default flow; adds a custodian.
- **BTCPay Server** -- needs a server this project does not have.
- **Gumroad, Substack, Polar, GitHub Sponsors, Ko-fi, Buy Me a Coffee, Payhip,
  Liberapay, Lemon Squeezy, Paddle, Open Collective** -- all require identity
  verification and none settles crypto to a seller-controlled address.

## Viable routes

- Wallet ask on the product page and in every article (already live).
- Put the receive address in the GitHub repo: FUNDING.yml, README, releases.
- Publish the product as a downloadable file on GitHub Releases.
- Ask in the artifact: README, --help output, docs footer.
- Ship the product free, sell the upgrade, ask in the README.
- Getly -- sell a digital product, settle USDT on Tron to your own wallet.
